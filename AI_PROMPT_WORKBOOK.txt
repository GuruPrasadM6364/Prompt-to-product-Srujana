2. PROMPT USED
--------------
Only the original product prompt is documented here:

"Build a working, demo-ready prototype called Circular Grid: a predictive
circular-resource grid for an eight-building campus. Use the supplied campus
data, verify its stated characteristics in code, and deliver the system in
phases with tests, measured results, and an honest report.

The requested system combines noisy, asynchronous campus electricity, water,
occupancy, manual-log, and smart-bin data. It must normalize building aliases
and units, deduplicate and reconcile readings, handle missing or late data,
retain offline buildings with clearly marked estimates, and report data
quality.

Train and compare waste classifiers using only the labeled training data.
Handle missing values and class imbalance, evaluate with cross-validation and
a time-based holdout, measure accuracy, macro-F1, per-class recall, model
size, and inference latency, and do not claim accuracy on the unlabeled test
file. Provide an edge inference path with a low-confidence manual-sort
fallback and test-file predictions.

Forecast building-level electricity, water, footfall, and waste at six- and
twelve-hour horizons. Compare against seasonal-naive and last-value
baselines with leakage-free rolling-origin evaluation. Report error and
spike-detection metrics, explain edge-versus-central deployment choices, and
show widening uncertainty for offline buildings.

Implement offline-capable edge buffering and central reconciliation with
idempotent uploads, sequence numbers, late-arrival handling, and outage
replay tests. Detect anomalies, rank evidence-backed root causes and
recommendations, and model circular compost allocation and an occupant
incentive loop with anti-gaming controls.

Include failure-mode mitigations, cost assumptions, and a measured synthetic
scale test. Build a useful facilities dashboard and a lightweight building
view, with accessible, restrained styling and honest estimated-data labels.
Do not invent data, fake metrics, or claim unmeasured results.

Provide reproducible setup, data, training, test, and run commands; document
architecture, assumptions, measured results, and limitations. Deliver the
classifier prediction CSV, requested dashboard screenshots, a three-page
report outline, and a short demo script. At completion, show exact commands
and any manual actions needed."

Purpose:
This was the project's high-level product and engineering brief. It defines
the expected data pipeline, ML evaluation, forecasting, offline behavior,
explainability, incentives, dashboard, quality gates, and submission
artifacts. The text above is a condensed description of the supplied prompt,
not a transcript of later prompts.

4. ITERATIONS AND IMPROVEMENTS
------------------------------
The original prompt itself requires phased work, running tests after each
phase, correcting issues before proceeding, using fixed seeds, and reporting
limitations honestly. It also gives concrete quality improvements to pursue:
- Verify data assumptions before relying on them.
- Preserve missing, stale, and offline cases instead of hiding them.
- Compare models and forecasts against explicit baselines using appropriate
  validation splits.
- Measure latency, model size, memory, and scale rather than asserting them.
- Label estimates and simulations, and never present test-file predictions as
  measured accuracy.
- Tie recommendations to visible evidence and state uncertainty.
